# 광고 · 결제 기획

> 상태: **기획만 정리. 구현 안 됨.**
> Verse8 지원 범위 기준 — 광고는 보상형/전면 2종, 결제는 VXShop(VX 통화, 게임 서버 필수).

> **구조가 바뀌었다 — 아래 기획은 옛 30스테이지 그리드 기준이다.**
> 지금 게임은 10일짜리 사무실 루프다. 스테이지 그리드와 타이틀 화면은 삭제됐고,
> "다음 빌드" 버튼도 없다 (빌드를 끝내면 사무실 바닥으로 돌아온다).
>
> 그래서 옛 기획 중 자리를 잃은 것과, 새 구조가 새로 여는 자리는 이렇다.
>
> | 옛 기획 | 지금 |
> |---|---|
> | 전면 광고 — 빌드 사이 | 자리 없음. 빌드 사이가 곧 사무실 이동이라 끊을 곳이 아니다. **하루 경계(잠자기 → 다음 날)** 가 유일하게 자연스러운 챕터 구분 |
> | 보상형 — 사망 후 이어하기 | 그대로 유효. 빌드 안에서만 일어나는 일이라 루프와 무관 |
> | 보상형 — 카테고리 좁히기 | 그대로 유효 |
> | 챕터 팩 (새 씬 묶음) | 그대로 유효. 오히려 더 맞는다 — 씬이 늘면 하루 세 개의 로테이션이 길어진다 |
> | 진행도 즉시 해금 | 대상이 사라졌다. 해금할 스테이지 목록이 없다 |
>
> **새 구조가 여는 자리: 시간과 장비.** 이 루프의 화폐는 시간이고, 상점(비품 신청서·택배)은
> 이미 게임 안에 있다. 돋보기·의자·알람은 지금 보수로만 살 수 있다 —
> 광고나 결제로 같은 것을 살 수 있게 하는 것이 이 게임에서 가장 자연스러운 상품이다.
> 단, **보고 기회 1회 규칙은 여전히 팔지 않는다** (아래 대전제 그대로).
>
> 상태: 구현 보류. 루프 밸런스가 잡힌 뒤에 붙인다.

## 대전제: 팔면 안 되는 것

이 게임의 상품성은 **"빌드당 보고 1회"** 라는 긴장감 하나에 걸려 있다.
따라서 아래는 어떤 형태로도 판매하지 않는다.

| 금지 | 이유 |
|---|---|
| 추가 보고 기회 | 핵심 규칙이 무너진다. 돈으로 찍기가 가능해지면 관찰할 이유가 사라짐 |
| 정답 공개 | 위와 동일. 게임을 사서 없애는 꼴 |
| 정답 대상 하이라이트 | 지목 단계를 통째로 건너뜀 |

파는 것은 **실패 비용을 줄이는 것**과 **콘텐츠·외형**으로 한정한다.

## 광고

Verse8 제약: 사용자 제스처에서만 호출, 타임아웃 30초, 보상은 서버 검증 후 지급.

### 보상형 — 1순위

**A. 사망 후 이어하기** (`placementId: "revive"`)
체력 0으로 죽었을 때 "광고 보고 이어하기". 체력을 회복하고 **같은 버그로** 이어서 진행.
- 규칙 안 깨짐: 보고 기회는 여전히 1회
- 죽음이 유일한 강제 종료 지점이라 동기가 자연스러움
- 빌드당 1회로 제한 (무한 부활 방지)

**B. 카테고리 좁히기 힌트** (`placementId: "hint-category"`)
5지선다를 **2지선다로 축소**. 오브젝트는 안 알려줌.
- 지목(관찰)은 그대로 남고 분류만 쉬워짐 — 게임의 핵심을 안 건드림
- 빌드당 1회
- 주의: 남발하면 학습을 방해함. 3스타 스테이지에서만 제공하는 것도 고려

### 전면 — 신중하게

**C. 빌드 사이 전환** (`placementId: "between-builds"`)
결과 화면의 **"다음 빌드" 버튼을 누를 때** 노출 (제스처 조건 충족).
- **3회 클리어당 1회**, 세션당 최대 3회 정도로 낮게
- 이 게임은 한 판이 1~3분으로 짧아서 전면 광고 빈도가 곧 이탈률임. 여기서 욕심내면 손해

**넣지 않을 것**: 배너 (Verse8 미지원이기도 하고, 360×640 세로 화면에서 필드를 잡아먹음), 게임 시작 시 자동 노출 (제스처 조건 위반).

## 결제 (VXShop)

VX는 플랫폼 통화. 구매 처리는 Verse8이 담당하고, **아이템 지급은 서버에서 관리해야 함**.

### 1. 광고 제거 — 영구

가장 확실한 상품. 전면 광고를 없애고 보상형은 남긴다(원하는 사람은 계속 시청 가능).
퍼즐 장르에서 전환율이 가장 높은 품목.

### 2. 힌트 팩 — 소모성

카테고리 좁히기 힌트 5개 / 15개 묶음. 광고 대신 즉시 사용.
광고와 같은 효과를 파는 구조라 **광고 제거 구매자에게도 의미가 있음**.

### 3. 챕터 팩 — 영구 · 장기적으로 가장 중요

새 씬 묶음(예: "우주 정거장 빌드" 4씬 + 스테이지 12개).
- 현재 구조상 씬 하나가 데이터 190줄이라 **추가 비용이 낮음**
- 30스테이지는 2~3시간이면 끝남. 재구매 동기가 여기밖에 없음
- 무료 30 + 유료 챕터 구조가 이 게임에 가장 맞는 수익 모델

### 4. 외형 — 영구

게임 화면 테마(다크 IDE 테마, CRT 필터, 흑백 디버그 뷰).
판정에 영향 없음. 단가 낮고 마진 좋음.
**주의**: 테마가 버그 가시성을 바꾸면 안 됨 — 대비를 낮추는 필터는 금지 (그림자·색 버그가 안 보이게 됨).

### 5. 서포터 팩 — 번들

광고 제거 + 힌트 15 + 테마 1종. 가장 높은 단가 상품.

### 팔지 않을 것

- 스테이지 스킵 (검증 없이 넘기면 게임을 안 한 것)
- 진행도 즉시 해금

## 구현 시 필요한 것

이미 붙어 있는 `server.js` 위에 얹으면 된다.

```js
// server.js 에 추가될 함수들
async grantHints(count)      // 결제/광고 보상 지급 — 서버 검증 후
async consumeHint()          // 힌트 1개 차감, 남은 수 반환
async getEntitlements()      // { adFree, hints, chapters: [], theme }
async setAdFree()            // 광고 제거 구매 반영
```

클라이언트는 [src/net/useProgress.ts](../src/net/useProgress.ts)와 같은 패턴으로
`useEntitlements.ts` 하나를 더 만들어 그쪽에서만 서버를 만지면 된다.

광고 SDK는 `@verse8/ads` 설치 후 `Verse8Ads.showRewarded({ placementId })`.
**보상 지급은 반드시 서버 검증 뒤에** — 클라이언트가 보상을 직접 주면 조작 가능.

## 정직한 전망

- 이 장르는 세션이 짧고 콘텐츠 소모가 빠르다. **광고 수익이 주(主), 결제가 보조**가 될 가능성이 높다
- 결제 중 실질적으로 의미 있는 건 **광고 제거**와 **챕터 팩** 둘뿐. 나머지는 부가
- 챕터 팩이 성립하려면 씬을 계속 만들어야 한다. 지금 엔진 구조는 그걸 싸게 만들 수 있게 돼 있음 — 수익 모델이 엔진 투자와 맞물려 있다
- 무료 30스테이지는 유지할 것. 이 게임은 "한 번 해보면 아는" 유형이라 체험 구간을 줄이면 전환이 오히려 떨어진다
