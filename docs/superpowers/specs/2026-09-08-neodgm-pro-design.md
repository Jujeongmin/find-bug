# 게임 글자를 Neo둥근모 Pro로

2026-09-08 · `develop`

## 문제

게임 전체가 `"Segoe UI", "Apple SD Gothic Neo", "Noto Sans KR", sans-serif` 하나를
쓴다. 웹폰트는 없고, NPC 말풍선도 예외가 아니다 — 말풍선이 달라 보였던 건 굵기(400,
나머지 UI는 대부분 700~800)와 크기(10px)와 바탕(크림색)이지 서체가 아니었다.

16px 픽셀 스프라이트로 그린 화면 위에 시스템 UI 서체가 얹혀 있으면, 그림은 게임인데
글자는 웹페이지다.

## 고른 것

[Neo둥근모 Pro](https://github.com/neodgm/neodgm-pro) · OFL 1.1 · **38,144 바이트**
(woff2). 1990년대 DOS 비트맵 서체 '둥근모꼴'을 아웃라인으로 옮긴 것의 가변폭 판.

후보 넷을 실제 게임 문자열로 렌더해 비교했다.

| | woff2 | 한글 | 비고 |
|---|---|---|---|
| Galmuri11 | 493KB | 4,358자 | 가장 정갈하지만 번들 JS(350KB)보다 무겁다 |
| Galmuri9 | 420KB | 4,358자 | 위와 같음 |
| Neo둥근모 | 44KB | 11,172자 | 고정폭 — 긴 문장이 늘어진다 |
| **Neo둥근모 Pro** | **37KB** | **11,172자** | 가변폭. 이걸로 간다 |

Galmuri의 용량은 대부분 JIS X 0208 한자 6,355자다. 서브셋으로 줄일 수는 있지만,
37KB에 한글 11,172자를 전부 주는 선택지가 있는데 그 작업을 할 이유가 없다.

## 1. 넣는 방법

`src/assets/fonts/neodgm_pro.woff2`에 두고 Vite로 번들한다. CDN 링크가 아닌 이유는
스프라이트 시트와 같다 — Verse8은 하위 경로로 서빙하므로 번들러가 URL을 다시 써야
한다(`spriteStyle.ts`의 주석이 같은 말을 한다).

`index.css`의 `body` 스택 **맨 앞**에 놓고, 지금 스택은 뒤에 그대로 남긴다. 이 폰트에
없는 글자 — 간체 한자 상당수 — 가 시스템 폰트로 떨어지게 하기 위해서다. 빈 네모보다
서체가 섞이는 쪽이 낫다.

`docs/ASSETS.md`에 OFL 1.1로 기재한다. 지금 문서는 첫 줄이 "모든 에셋 CC0"인데,
Messy Furniture가 이미 그 문장의 예외이므로 그 문장부터 손봐야 한다.

그리고 CC0와 달리 **OFL은 의무가 있다** — 폰트를 번들에 담아 배포하므로 라이선스
전문이 같이 가야 한다. `src/assets/fonts/OFL.txt`로 폰트 옆에 둔다.

## 2. 굵기는 그대로 둔다

이 폰트는 Regular 한 벌뿐이다. 게임이 쓰는 700/800은 브라우저가 합성한다.

실제로 렌더해 보니 읽을 만하고, 무엇보다 **글자 폭이 변하지 않는다** — 합성 굵게가
전진폭을 건드리지 않으므로 줄바꿈 계산에 영향이 없다(400과 800의 `measureText` 결과가
바이트 단위로 같다). 그래서 굵기 규칙 40여 개를 손대지 않는다.

## 3. 글자가 넓어진다

12px 실측 전진폭:

| | 지금 | Neo둥근모 Pro | |
|---|---|---|---|
| 한글 | 11.04 | **12.00** | +8.7% |
| `…` | 8.79 | **11.25** | +28% |
| 숫자 | 6.47 | 6.00 | −7% |
| 라틴 소문자 | 5.55 | 5.40 | −3% |

한글이 8.7% 넓어지므로, 아슬아슬하게 한 줄이던 것이 두 줄이 된다. 확인된 곳은 퀘스트
칩과 좌상단 날짜 칩이다.

### 퀘스트 칩은 폰트 문제가 아니다

`.quest`는 `left: 50%` + `transform: translateX(-50%)`로 가운데 정렬한다. 절대 위치
요소의 shrink-to-fit 가용 폭은 `containing block − left`이므로, **프레임의 절반**만
쓴다. 380px 화면에서 190px다. `max-width: calc(100% - 24px)`는 356px를 허용하지만 그
앞에서 이미 잘린다.

지금 서체로는 한 줄이 166px라 190 안에 겨우 들어갔고, 그래서 이 결함이 드러나지
않았다. 새 서체로는 180px가 되어 넘친다.

고치는 방법은 문구를 줄이는 게 아니라 폭을 되찾는 것이다:

```css
left: 0;
right: 0;
transform: none;
margin-inline: auto;
width: max-content;
```

측정: `190px / 2줄` → `203px / 1줄`. 문구는 그대로다.

### 나머지

좌상단 날짜 칩을 포함해, 화면을 실제로 돌면서 넘친 곳을 개별로 잡는다. 미리 목록을
만들지 않는 이유는 만들 수 없기 때문이다 — 어디가 넘치는지는 렌더해 봐야 안다.

## 4. `checkquest.ts` 재보정

지금 모델은 "한글·한자 = 폰트 크기, 나머지 = 0.52배"다. 새 서체는 픽셀 격자 위에
그려져서 전진폭이 정확한 분수다:

| 문자 | 폰트 크기 대비 |
|---|---|
| 한글 · 가나 · 한자 · `—` | 1.0 |
| `…` | 0.9375 |
| 숫자 | 0.5 |
| 라틴 | 0.45 ~ 0.48 |
| 공백 · `·` | 0.3125 |

`…`을 0.52로 세던 것이 실제로는 0.94다. 방금 퀘스트 11줄 전부에 `…`을 붙였으므로 이
오차가 모든 줄에 한 번씩 쌓인다.

예산 200px도 실측과 맞지 않는다. 3번을 고치기 전의 실제 가용 폭은 168px이다(칩 190 −
좌우 안쪽 여백 22). 고친 뒤에는 프레임 폭이 그대로 예산이 된다.

프레임은 `min(100vw, 100dvh × 9/16)`이라 폰마다 다르다. 좁은 쪽을 기준으로 360px를
잡고 거기서 빼면:

```
360  프레임
−24  max-width: calc(100% - 24px)
−22  padding: 4px 11px 좌우
───
314  한 줄에 들어가야 하는 글자 폭
```

`BUDGET = 314`. 지금의 200은 좁게 잡은 값이었는데, 계산 모델이 `…`을 실제의 절반으로
세고 있었으므로 두 오차가 서로를 가려 왔다.
