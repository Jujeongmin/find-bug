# 다시 할 이유: 연차, 시작 선물, 새 빌드 둘

2026-09-15 · `develop`

## 문제

12일을 끝내면 "타이틀로" 버튼 하나가 나오고, 누르면 1일차 0원으로 돌아간다.
2회차는 1회차와 같다.

- `assignDay`는 완전히 결정적이다. `BUILD_IDS[(day * 5 + i) % BUILD_IDS.length]` —
  3일차 A번 기기는 몇 회차든 같은 씬, 같은 심각도다. 회차마다 달라지는 건 기기에
  심어지는 결함 하나뿐이다.
- 회차를 넘어 남는 것은 결함 수첩, 계정의 `best`·`runs`, `remove-ads` 구매다.
  수첩은 기록만 하고 여는 것이 없다. `best`·`runs`는 서버가 쓰기만 하고 클라이언트가
  한 번도 읽지 않는다.
- `reportRun`은 서버가 없으면 첫 줄에서 돌아간다. 오프라인으로 끝낸 회차는 어디에도
  세어지지 않는다.

결제가 있는 게임에서 두 번째 회차를 시작할 이유가 "점수를 더 잘 받기" 하나뿐이다.

## 결정

| 질문 | 답 |
|---|---|
| 목적 | 리텐션 — 2회차가 1회차와 **달라야** 한다. 쉬워질 필요는 없다 |
| 무엇이 여나 | 회차 완료 = 연차. 성과로 막지 않는다 |
| 1년차 | 지금 그대로. 신규 플레이어 경험은 한 글자도 안 바뀐다 |
| 새 콘텐츠 | 기존 위에 추가. 2년차 광산, 3년차 주방 |
| 직접 혜택 | 2년차부터 회차 첫 아침에 장비 하나를 골라 들고 시작 (재검토 제외) |
| 4년차 이후 | 연차 표시와 시작 선물만. 새 씬은 반응을 보고 추가 |

지키는 원칙 하나: `docs/MONETIZATION.md`에 적힌 **한 회차 수입(약 704원)이 사고
싶은 것(약 930원)보다 적다**는 긴장. 돈이나 산 장비를 통째로 넘기지 않는 이유다.

## 1. 연차 기록 — 끝낸 회차 id의 집합

연차는 숫자가 아니라 **끝낸 회차 id의 집합**에서 나온다.
`연차 = min(집합 크기, 98) + 1`.

숫자 max로 합치면 틀린다. 기기 A와 B에서 각각 오프라인으로 한 회차씩 끝내면 로컬은
둘 다 1이고 max도 1이다. 실제로는 두 회차다. 게다가 지금 `reportRun`은 서버에서
`runs + 1`을 하므로 재시도하면 두 번 센다. 수첩이 이미 쓰는 방식, 합집합이 맞다.

| 자리 | 무엇 |
|---|---|
| 회차 시작 | `RunFields`에 `runId`(`r` + 소문자·숫자 12자)와 `yearAtStart` 고정. `codexAtStart`와 같은 방식 |
| 로컬 | `fb_years_v1` = 끝낸 id 배열. 그림은 로컬이 기준이라 서버 없이도 동작한다 |
| 계정 | `state.finished` 배열. 새 서버 함수 `syncYears(ids)`가 합집합을 돌려준다 |
| 출시 화면 | 로컬에 `runId`를 더하고 `syncYears`. 기존 `reportRun`(best·runs)은 그대로 둔다 |
| 초기화 | `resetSave`가 `finished: []`도 비운다. 로컬도 비운다. 오프라인 초기화는 기존 `fb_reset_owed` 경로를 탄다 |
| 상한 | 배열 99개. 차면 새 id는 버린다 — 로컬도 계정도. 연차는 99에서 멈춘다 |

**고정 원칙.** 회차 도중 다른 기기에서 연차가 올라가도 이번 회차의 빌드 풀·선물·수첩
분모는 `yearAtStart`를 따른다. 부팅 2초 안에 계정이 안 오면 로컬 연차로 시작하고,
나중에 계정이 더 높다고 해도 이번 회차는 바뀌지 않는다.

**기존 플레이어 이관.** 이미 12일을 끝낸 사람이 업데이트 후 1년차로 떨어지면 안
된다. 계정의 `runs`가 그 근거다.

이관은 **계정에 `finished` 필드가 처음 생기는 순간 한 번만** 한다. 그 순간
`legacy = max(0, runs − 이번 호출로 들어온 id 수)`개의 `legacy-1`, `legacy-2`, …를
채우고 `finished`를 만든다. 그 뒤로는 `runs`를 다시 보지 않는다.

매번 비교하면 틀린다. 출시 화면에서 `reportRun`은 성공하고 `syncYears`는 아직 안
갔을 때 계정은 `runs: 4, finished: []`이다. 그때 다른 기기가 부팅해서 동기화하면
`legacy-1..4`가 붙고, 뒤늦게 도착한 이번 회차 id까지 더해 5가 된다. 한 번만 하면
그 뒤의 `runs` 증가는 연차에 영향을 주지 않는다.

같은 이유로 **출시 화면은 `reportRun`이 끝난 뒤에 `syncYears`를 부른다.** 동시에
보내면 이관 순간 읽은 `runs`에 이번 회차가 들어 있을 수도, 없을 수도 있다.

로컬에만 있던 업데이트 전 오프라인 기록은 셀 근거가 없어서 살리지 못한다.

**업데이트 전에 시작한 회차.** `yearAtStart`가 없으니 1로 읽는다. 선물도 새 씬도
없다. 정직한 기본값이다.

**검증 형식.** 서버와 클라이언트에 자유 문자열 필드 타입이 없다. `runId` 전용
검사기를 양쪽에 하나씩 둔다. 서버 쪽은 `ENTRY_ID`와 같은 정규식 방식이고,
`legacy-N`도 받는다. `yearAtStart`는 `["n", 1, 99]`.

## 2. 시작 선물

**언제.** `yearAtStart >= 2`이고 `gift`가 아직 `null`인 회차의 1일차 아침. 기존
아침 문구보다 먼저 뜬다.

지금 아침 문구는 마운트 때 `setNote(morningLine())`로 바로 뜬다. 선물이 필요한
회차에서는 그 호출을 건너뛰고, 선물을 고르는 순간 아침 문구를 띄운다. 두 창이 겹쳐
뜨면 안 된다.

**무엇.** 재검토 요청서를 뺀 다섯 가지 중 하나: 돋보기, 좋은 의자, 알람시계, 좋은
신발, 보온병. 회사 상점과 집 상점 물건을 한 창에 섞는다.

재검토를 빼는 이유. 나머지 다섯은 속도나 시야를 바꾸지만 재검토는 틀린 보고를 없던
일로 만든다. 브리핑이 "보고는 빌드당 한 번뿐이다"라고 말하는 게임에서 매 회차
공짜로 주면 매 회차 틀린 보고 하나가 남지 않는다. 사서 쓰는 건 여전히 된다.

**모양.** 기존 `.modal.shop` 마크업을 그대로 쓴다. 제목 `{n}년차 첫 출근 — 하나
챙겨가자`, 가격 자리에 `챙기기`. 배경을 탭해도 닫히지 않고 닫기 버튼도 없다. 고르는
것이 유일한 출구다. 실수로 닫아 선물을 날리면 안 된다.

**지급.** 상점 `buy`와 같은 `setOwned((o) => [...o, item])`에서 돈만 빼지 않는다.
상점에 들어가면 그 물건은 "보유 중"이다.

**저장.** `RunFields.gift: ItemId | null`. 고르는 도중 새로고침하면 다시 묻고, 고른
뒤에는 묻지 않는다. 서버 규칙 `["s", [null, "magnifier", "chair", "alarm", "shoes", "thermos"]]`.

**돈 긴장.** 선물 최대 가치는 좋은 의자 160원이다. 사고 싶은 것 약 930원에서 빼면
약 770원이고, 여전히 한 회차 수입보다 크다.

## 3. 빌드 풀과 수첩, 출시 화면

**등록.** `ENGINE_SCENES`에는 모든 씬을 그대로 둔다. 검사 스크립트와 DebugLab이
전부 봐야 한다. `registry.ts`에 연차 표만 더한다:

```ts
export const SCENE_YEAR: Record<string, number> = { stage08: 2, stage09: 3 };
// 표에 없는 씬은 1년차
```

**빌드 목록.** `BUILD_IDS` 상수를 `buildIdsFor(year)`로 바꾼다. 1년차 목록은 지금
순서 그대로 **명시 상수**로 고정하고, 새 씬은 연차 순으로 뒤에 붙인다.

| 연차 | 목록 길이 | 보폭 5와 서로소 |
|---|---|---|
| 1 | 7 | ✓ |
| 2 | 8 | ✓ |
| 3 이상 | 9 | ✓ |

`assignDay(day, year)`. 목록 길이가 4 이상이라 하루 네 기기에 같은 씬이 두 번 오지
않는다.

**수첩.** `codexRows(book, year)`는 잠긴 씬 결함을 행과 분모에서 뺀다. 1년차 수첩은
지금과 같은 분모다. 호출 세 곳(`codexAtStart` 초기화, 출시 화면, 수첩 모달)에
`yearAtStart`를 넘긴다.

**출시 화면.** 수첩 줄 아래 한 줄.
- 다음 연차에 새 빌드가 열리면: `다음은 {n}년차 — 새 빌드 '{이름}'이 들어온다`
- 1년차에서 2년차로 갈 때 덧붙임: `첫 출근에 장비 하나를 챙겨간다`
- 새 것이 없으면: `다음은 {n}년차`

**연차 첫 아침.** 선물 창 다음에 `home.morningYear` — `{n}년차. 다시 12일이다.`
그 연차에 새 빌드가 열렸으면 `새 빌드 '{이름}'이 들어왔다.`를 붙인다. 1년차는 기존
`home.morningFirst` / `home.morningFirstAgain` 그대로다.

## 4. 새 빌드 둘

두 씬 모두 엔진 코드가 필요 없다. `links`, `triggered` 클래스, `toggle`, `pressure`,
`meter`, `flagged`는 런타임(`runtime.ts:674`)과 렌더러(`EngineStage.tsx:880`)에 이미
구현돼 있다. 게이지 장치는 지금까지 어느 씬도 쓰지 않았다.

설계 원칙은 자판기 씬과 제외 목록이 이미 적어둔 것이다. 결함은 플레이어가 이미 가진
직관을 어겨야 읽힌다.

`dungeon.png`는 저장소에 있지만 어느 씬도 쓰지 않는다. 레버만 이 시트에 없어서
`platformer.png`에서 가져온다. 외곽선 굵기와 갈색 계열이 같다.

| 오브젝트 | 그림 (col,row) | 행동 | 노리는 결함 |
|---|---|---|---|
| 플레이어 | platchars (0,1) — 기존 스테이지와 같음 | `playerTopDown` | 없음. 상자 줍기와 해골 접촉에 필요하다 |
| 금화 HUD | — | `counter` 표시 오브젝트 | 없음. `counterSkew`는 **보이는** 카운터가 있어야 후보가 된다 |

횃불 불꽃 멈춤은 처음부터 노리지 않는다. 촛불 두 개를 비교하게 했던 전례가 "인내심
테스트"로 제외됐다.

광차 순간이동은 사격장 과녁을 뺀 논리와 부딪칠 수 있다. 광차는 레일 끝에 멈춤목이
보여서 과녁보다 기대가 분명하다고 판단해 넣는다. 만든 뒤 검토에서 안 읽히면 뺀다.

정상인 짝이 있다. 거꾸로 된 쪽 냄비도 끓고 있으니 "바늘이 틀렸다"가 한눈에 보인다.

### 두 씬 공통

- id가 서버 수첩 정규식 `^stage\d{2}\/…` 을 통과한다
- 이름·목표·브리핑·오브젝트 이름 i18n 키가 다섯 언어(en, ja, ko, zh-Hans, zh-Hant)
  전부에 있다
- `checkscenes`, `checkcurriculum` 통과. 결함 수가 `MIN_POOL`(3) 이상
- 만든 뒤 `npm run report`로 결함을 하나씩 보고, 직관을 어기지 않는 것은
  `exclusions.ts`에 사유와 함께 뺀다

## 5. 구현 순서

한 번에 하나씩 끝내고 커밋·푸시한다. 앞 단계만으로도 게임이 성립한다.

구현 계획은 셋으로 나눈다. **뼈대**(1~3), **광산**(4), **주방**(5). 뼈대가 배포되고
나서 씬 계획을 쓴다 — 씬은 뼈대 위에 등록 한 줄로 얹히므로 뼈대가 먼저 확정돼야
한다.

1. 연차 기록 — `runId`·`yearAtStart`, 로컬 집합, `syncYears`, 이관, 초기화
2. 빌드 풀 게이팅과 수첩 분모 — 이 시점엔 `SCENE_YEAR`가 비어 있어서 화면이 바뀌지
   않는다. 1년차 골든 스냅샷이 그걸 증명한다
3. 시작 선물과 연차 문구, 출시 화면 한 줄
4. `stage08` 광산 — `SCENE_YEAR`에 등록하면서 열린다
5. `stage09` 주방

## 6. 검증

**`scripts/checkyears.ts` (새로 만듦)**
- 합집합: 두 기기 각 1회차는 연차 3
- 중복: 같은 `runId`를 두 번 보고해도 한 번만 센다
- 이관: `runs: 3`이고 `finished` 필드가 없으면 연차 4
- 이관은 한 번만: 이관 뒤 `runs`가 늘어나도 `legacy-*`는 더 붙지 않는다
- 이관 순간 들어온 id가 있으면 그만큼 뺀다: `runs: 4`에 `rX` 하나가 들어오면
  `legacy-1..3` + `rX` = 연차 5
- 초기화 뒤 연차 1
- 상한: 99개를 넘는 id는 받지 않는다
- `runId` 검사기: 형식이 틀리면 버린다. `legacy-N`은 받는다
